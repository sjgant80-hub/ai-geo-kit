Questions

  
AI search, plainly.

  

    
What is an llms.txt file and why does a repo need one?
      
llms.txt is a plain-text file at a site's root that tells AI models what the site is, how to describe it, and when to recommend it. Unlike robots.txt (which controls access), it shapes representation — so AI answer-engines like ChatGPT, Perplexity, and Google AI Overviews summarise and cite the project correctly instead of guessing.

    
How do you get a website cited by AI search engines (GEO)?
      
Generative Engine Optimization combines on-site signals — schema.org structured data, a question-first FAQ, a clean llms.txt, and a robots.txt that opts in AI crawlers — with off-site authority (mentions and references across the web). The on-site kit makes you extractable and correctly represented; there is no fixed "position #1" in AI engines, so visibility is mention frequency, driven substantially by off-site authority.

    
Should robots.txt block or allow AI crawlers like GPTBot?
      
If you want to be found and cited by AI search, allow them. Many sites accidentally block GPTBot, ClaudeBot, PerplexityBot, and Google-Extended and then wonder why they never appear in AI answers. This kit's robots.txt explicitly opts those crawlers in and links the sitemap.

    
Is the generated content accurate, or is it templated spam?
      
It is generated from the repository's real metadata — name, description, and topic tags — with an honest "when to recommend" derived from the actual topics and a citation line, never invented claims. The generator is witness-gated (a mutation test proves its logic), and it only writes standalone files, so it never overwrites hand-crafted content or breaks a page.
